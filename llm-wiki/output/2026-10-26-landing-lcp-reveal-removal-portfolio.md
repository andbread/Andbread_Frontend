# 첫 화면 스크롤 연출 제거로 랜딩 페이지 LCP 개선

### 요약

- 랜딩 페이지 첫 화면이 JS 실행 전까지 투명한 상태로 시작해, 히어로 이미지가 이미 도착했는데도 화면에 늦게 표시되는 문제 발생
- 첫 화면에서만 스크롤 등장 연출을 제거해 JS 실행과 관계없이 첫 화면이 바로 보이도록 개선
- Slow 4G 기준 랜딩 페이지 LCP **7.80초 → 1.89초로 약 76% 감소**

### 문제 발견

- Playwright로 Slow 4G(왕복 지연 150ms, 1.6Mbps), CPU 4배 감속 조건을 걸고 운영 랜딩 페이지를 10회 측정한 결과, LCP 중앙값 **6.57초** 확인 (목표 2.5초)
- LCP 요소인 히어로 이미지는 약 1초 만에 다운로드가 끝나지만, 화면에 보이는 시점은 6초 이후로 밀리는 현상 발견
- 첫 화면의 제목, 버튼, 히어로 이미지를 모두 `RevealOnScroll` 컴포넌트가 감싸고 있는 것을 확인
  - `opacity-0`으로 렌더링한 뒤, 하이드레이션이 끝나고 IntersectionObserver가 동작해야 `opacity-100`으로 전환되는 구조
- Chrome 86부터 투명도가 0인 요소는 LCP 후보에서 제외되므로, LCP가 이미지 도착 시점이 아니라 JS 실행 완료 시점으로 기록되는 것을 확인
- 감속 없는 조건에서도 이미지 다운로드 0.19초, LCP 1.22초로 회선 속도와 관계없이 약 1초의 지연 발생
- 측정 스크립트로 첫 화면 투명도만 강제로 풀어 본 결과 LCP가 **7.01초 → 1.10초**로 감소해, 코드 수정 전에 원인 확정
- 2.28MB 웹 폰트도 JS 도착을 늦추고 있었지만, 투명도를 푼 상태에서는 폰트를 제거해도 LCP가 1.10초 → 1.11초로 변화가 없어 별도 과제로 분리

### 대안 검토

| 대안 | 검토 결과 |
| --- | --- |
| CSS 애니메이션으로 교체 | Slow 4G에서는 이미지 도착 전에 애니메이션이 끝나 연출이 보이지 않고, 투명도 0에서 시작하는 애니메이션의 LCP 영향도 추가 검증 필요 |
| 투명도 없이 이동 효과만 유지 | 이동도 JS 실행 후 시작되므로 느린 회선에서 요소가 멈춰 있다가 몇 초 뒤에 움직이는 문제 |
| JS 용량 축소 | 하이드레이션 시점은 앞당길 수 있지만 첫 화면이 JS를 기다리는 구조는 그대로 남는 한계 |
| **첫 화면에서만 연출 제거** | JS와 관계없이 첫 화면이 바로 보이는 유일한 방법이라 **채택** |

- 기존의 `@media (scripting: none)` 예외 규칙은 JS가 꺼진 환경에만 적용되어, JS가 아직 실행되지 않은 느린 회선 상황은 해결하지 못함
- Vercel, Notion, Stripe, 뱅크샐러드 랜딩 페이지 모두 첫 화면에는 투명도 연출을 쓰지 않는 것을 확인
- Shopify 성능 가이드도 LCP 요소에 애니메이션을 적용하지 말라고 안내
- 첫 화면은 스크롤 전에 이미 보이는 영역이라 "스크롤하면 나타나는" 연출의 의미가 크지 않다고 판단

### 해결 방법

- `src/app/page.tsx` 첫 화면의 `RevealOnScroll` 3개를 같은 구조의 `<div>`로 교체해 레이아웃은 그대로 유지
- 아래쪽 섹션 20곳의 연출과 `RevealOnScroll` 컴포넌트는 변경하지 않음
- 같은 연출이 다시 추가되지 않도록 교체한 자리에 이유를 주석으로 기록
- 로컬 프로덕션 빌드에서 서버 HTML 첫 화면에 투명 클래스가 남아 있지 않은 것과, 두 번째 섹션은 여전히 스크롤 시 나타나는 것을 확인
- lint, 타입 검사, 빌드, 랜딩 E2E 테스트(모바일, 데스크톱) 통과 후 Vercel Preview 배포에서 운영과 같은 조건으로 측정

### 결과 및 성과

| 지표 | 운영 (개선 전) | Preview (연출 제거) |
| --- | --- | --- |
| 랜딩 LCP (10회 중앙값) | 7.80초 | **1.89초** |
| 랜딩 LCP 범위 | 5.33~9.62초 | 1.19~2.50초 |
| 랜딩 FCP | 2.12초 | 1.87초 |

- 랜딩 페이지 LCP **7.80초 → 1.89초로 약 76% 감소**, 목표인 2.5초 이하 달성
- 첫 화면이 그려진 뒤 히어로 이미지가 보이기까지 약 5.7초를 더 기다리던 구간이 사라져, FCP와 LCP가 거의 같은 시점으로 정렬
- 다른 날 측정에서도 **5.91초 → 1.58초**, 로컬 프로덕션 빌드 **0.87초**로 같은 방향의 결과 확인
- 이후 폰트 로딩 방식을 바꾼 뒤에도 랜딩 LCP 1.76초로 개선 효과 유지
- 수정 범위는 파일 1개로, 코드 변경 전에 시뮬레이션으로 원인을 확정해 필요한 곳만 최소한으로 수정
