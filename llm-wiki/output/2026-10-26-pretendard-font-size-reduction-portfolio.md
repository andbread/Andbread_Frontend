# Pretendard dynamic subset 적용으로 웹 폰트 용량 개선

### 요약

- 모든 페이지가 한글 전체 글자가 든 Pretendard 폰트 파일을 내려받아, 랜딩 페이지 용량의 81%를 폰트가 차지하는 문제 발생
- 화면에 나온 글자가 든 조각만 내려받는 dynamic subset 방식으로 폰트 로딩 방식 개선
- 첫 방문 폰트 용량 랜딩 **2,285KB → 389KB로 약 83% 감소**, 로그인 **2,285KB → 174KB로 약 92% 감소**

### 문제 발견

- 랜딩 페이지가 내려받는 파일을 확인한 결과, Pretendard 폰트 3개(Regular, Medium, Bold)가 각 약 750KB, 합계 **2,285KB**로 페이지 전체 용량의 81%를 차지
- `src/app/layout.tsx`에서 jsdelivr CDN의 `pretendard.css`를 불러오고 있었고, 이 CSS가 글자를 줄이지 않은 전체 폰트 파일을 사용하는 것을 확인
- `font-display: swap` 설정으로 화면 표시는 막지 않지만, Slow 4G에서는 폰트 다운로드 완료까지 **14.5초** 동안 기본 글꼴로 표시
- 폰트를 제거하고 측정한 결과 마지막 JS 도착이 4.2초 → 2.7초로 당겨져, 폰트가 JS와 회선을 나눠 쓰면서 JS 도착을 약 1.5초 늦추는 것을 확인
- JS 실행 후 본문을 그리는 로그인 페이지는 폰트 제거 시 LCP가 5.52초 → 3.60초로 감소
- 랜딩 페이지는 첫 화면 연출 제거 후 폰트 유무와 관계없이 LCP가 약 1.1초로 같아, 폰트 개선 목표를 LCP가 아닌 첫 방문 데이터 사용량과 글꼴 적용 시간으로 설정

### 대안 검토

운영 사이트에서 브라우저가 받는 폰트 CSS만 후보별로 바꿔 넣고 10회씩 측정해 비교

| 대안 | 랜딩 폰트 용량 | 폰트 다운로드 완료 | 검토 결과 |
| --- | --- | --- | --- |
| 현재 방식 (전체 폰트) | 3개, 2,285KB | 14.5초 | 기준 |
| 고정 서브셋 | 3개, 790KB | 7.2초 | 서브셋에 없는 희귀 글자가 기본 글꼴로 표시되어 제외 |
| dynamic subset, 저장소에서 직접 제공 | 33개, 388KB | 4.1초 | 외부 의존은 사라지지만 조각 파일 828개, 약 10.2MB를 저장소에서 관리해야 하는 부담 |
| **dynamic subset, CDN 유지** | 33개, 388KB | 4.1초 | 코드 한 줄 변경으로 같은 용량 감소 효과를 얻을 수 있어 **채택** |

- 그룹 이름, 채팅처럼 사용자가 직접 입력한 희귀 글자도 Pretendard로 표시해야 한다는 기준을 먼저 세워 고정 서브셋 제외
- dynamic subset은 전체 글자를 굵기마다 92개 조각으로 나누고 `unicode-range`로 필요한 조각만 받기 때문에 희귀 글자도 표시 가능
- 저장소 직접 제공 방식의 장점(외부 의존, 연결 비용 제거)은 기존에도 감수하던 비용을 줄이는 것이고, 대신 수백 개 파일과 캐시 설정이라는 새로운 관리 부담이 생긴다고 판단

### 해결 방법

```diff
- https://cdn.jsdelivr.net/gh/orioncactus/pretendard/dist/web/static/pretendard.css
+ https://cdn.jsdelivr.net/gh/orioncactus/pretendard@v1.3.9/dist/web/static/pretendard-dynamic-subset.css
```

- `src/app/layout.tsx`의 폰트 CSS 주소를 dynamic subset으로 교체
- 기존 주소는 버전이 없어 Pretendard 새 버전이 나오면 글꼴이 예고 없이 바뀔 수 있으므로, 당시 최신인 `v1.3.9`로 버전 고정
- 버전 없는 주소와 고정한 주소의 CSS 내용이 같은 것을 해시로 확인해 글꼴 모양 변화 없음을 검증
- 글꼴 이름, 굵기 9종, `font-display: swap` 설정이 기존과 같아 Tailwind 설정과 전역 CSS는 변경하지 않음
- 로컬 프로덕션 빌드에서 희귀 글자(똠, 햏, 뷁, 쀍)를 추가해 해당 조각을 추가로 받고 Pretendard로 표시되는 것을 확인
- lint, 타입 검사, 빌드, 랜딩 E2E 테스트 통과 후 Vercel Preview 배포에서 변경 전 배포와 번갈아 10회씩 측정

### 결과 및 성과

| 페이지 | 지표 | 변경 전 | 변경 후 |
| --- | --- | --- | --- |
| 랜딩 | 폰트 다운로드 | 3개, 2,285KB | **33개, 389KB** |
| | 폰트 다운로드 완료 | 15.31초 | **4.86초** |
| | LCP | 1.89초 | 1.76초 |
| 로그인 | 폰트 다운로드 | 3개, 2,285KB | **14개, 174KB** |
| | 폰트 다운로드 완료 | 14.65초 | **7.26초** |
| | 마지막 JS 도착 | 4.61초 | **3.75초** |

- 첫 방문 폰트 용량 랜딩 **2,285KB → 389KB로 약 83% 감소**, 로그인 **2,285KB → 174KB로 약 92% 감소**
- Slow 4G 기준 폰트 다운로드 완료 시간 랜딩 **15.31초 → 4.86초로 약 68% 단축**, 로그인 **14.65초 → 7.26초로 약 50% 단축**
- 로그인 페이지 마지막 JS 도착 **4.61초 → 3.75초로 약 0.9초 단축**
- 랜딩 LCP는 1.89초 → 1.76초로 나빠지지 않아 첫 화면 개선 효과 유지
- 개선과 함께 생긴 비용도 측정해 기록
  - 랜딩 페이지는 폰트 조각 33개가 JS와 같은 시간대에 요청되면서 마지막 JS 도착이 약 0.8초 늦어짐
  - 조각이 도착하는 순서대로 글꼴이 바뀌어 랜딩 페이지에서 약 0.4초 동안 Pretendard와 기본 글꼴이 섞여 보이는 구간 발생
  - 버전을 고정한 주소는 jsdelivr의 압축 수준이 달라 CSS 전송 크기가 13.8KB → 21.6KB로 커졌지만, Slow 4G 기준 약 0.04초 차이라 버전 고정 유지
