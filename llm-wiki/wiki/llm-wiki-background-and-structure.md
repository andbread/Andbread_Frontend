# llm-wiki 배경과 구조

## 한 문장 요약

llm-wiki는 여러 에이전트와 여러 PC에서 흩어지는 프로젝트 지식과 작업 맥락을 저장소 안에서 공유하기 위해 만든 구조다.

## 배경과 기존 문제점

- 여러 에이전트와 여러 PC에서 동시에 작업하면서 프로젝트 지식과 작업 맥락이 환경별로 흩어질 수 있다.
- 에이전트가 공통으로 참조할 저장 위치가 없어 같은 내용을 반복해서 설명하거나 서로 다른 기준으로 작업할 가능성이 있다.
- 지식 문서를 쌓기 전에 저장 위치와 분류 기준을 먼저 정하지 않으면 문서가 여러 위치에 분산될 수 있다.

## llm-wiki가 해결할 수 있는 것

- 저장소 안에 LLM 위키의 루트 디렉토리와 목적별 하위 디렉토리를 마련한다.
- 각 디렉토리의 용도를 확인할 수 있는 최소 안내 파일을 둔다.
- 여러 에이전트와 여러 PC가 같은 위키 구조를 깃을 통해 공유할 수 있게 한다.
- 다만 이번 범위는 구조와 최소 안내 파일까지다. 실제 지식 문서 작성, 에이전트별 자동 연동, 외부 위키 연동, 문서 자동화는 이번 범위에 포함하지 않는다.

## llm-wiki의 대략적인 구조

```text
llm-wiki/
  index.md      # 핵심 질문, 먼저 읽을 문서, 최근 산출물만 담는 최소 안내판
  log.md        # 자료 추가, 문서 생성, 확인 필요 사항을 표로 남기는 처리 이력
  AGENTS.md     # 위키 작업 규칙 (원본 보존, 파일명, 위키 작성, 산출물 작업, 로그 작성, 답변 원칙)
  CLAUDE.md     # `@AGENTS.md` 한 줄로 규칙을 import
  raw/          # 원본 자료 보관. 파일명은 `{YYYY-MM-DD}-{주제}.md` 형식을 쓴다.
  wiki/         # 원본을 바탕으로 정리한 지식 문서. `template.md` 형식(한 문장 요약, 근거, 확인된 내용, 확인 필요)을 재사용한다.
  output/       # 보고서, 요약문, 실행 계획 등 외부 공유용 산출물을 둔다.
```

- `raw/`와 `output/`은 빈 폴더 상태로도 git에 유지되도록 `.gitkeep`을 둔다.
- `wiki/` 아래 도메인별 하위 폴더는 아직 두지 않는다. 문서 수가 늘어 찾기 불편해지면 그때 나누기로 했다.
