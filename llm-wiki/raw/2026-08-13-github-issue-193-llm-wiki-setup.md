# [setting-74/llm-wiki] LLM 위키 디렉토리 구조 구축

출처: https://github.com/andbread/Andbread_Frontend/issues/193
확인 날짜: 2026-08-13
자료 성격: GitHub Issue (작업 기획서)

## Summary

> 클로드 코드, 코덱스 등 여러 에이전트와 여러 피시에서 공통으로 참조할 수 있는 LLM 위키 기반을 마련합니다.
> 이번 작업은 저장소 안에 위키 디렉토리 구조와 최소 안내 파일만 추가합니다.
> 실제 지식 문서 작성과 자동 동기화는 후속 작업으로 분리합니다.

---

## Why

### 해결하려는 문제가 무엇인가요?

- 여러 에이전트와 여러 피시에서 동시에 작업하면서 프로젝트 지식과 작업 맥락이 환경별로 흩어질 수 있습니다.
- 에이전트가 공통으로 참조할 저장 위치가 없어 같은 내용을 반복해서 설명하거나 서로 다른 기준으로 작업할 가능성이 있습니다.
- 지식 문서를 쌓기 전에 저장 위치와 분류 기준을 먼저 정하지 않으면 문서가 여러 위치에 분산될 수 있습니다.

---

## Goal

### 완료되면 무엇이 달라지나요?

- 저장소 안에 LLM 위키의 루트 디렉토리와 목적별 하위 디렉토리가 마련됩니다.
- 각 디렉토리의 용도를 확인할 수 있는 최소 안내 파일이 추가됩니다.
- 여러 에이전트와 여러 피시가 같은 위키 구조를 깃을 통해 공유할 수 있습니다.

이번 작업에서 해결하지 않는 범위(Non-goal)

- 실제 프로젝트 지식과 작업 기록을 본격적으로 작성하지 않습니다.
- 클로드 코드, 코덱스 등 에이전트별 설정이나 자동 참조 규칙을 변경하지 않습니다.
- 외부 위키 서비스 연동이나 자동 동기화를 구현하지 않습니다.
- 문서 생성, 검증, 정리 자동화를 구현하지 않습니다.

---

## Approach

### 어떻게 해결할 계획인가요?

- 저장소 안에서 모든 에이전트가 접근할 수 있는 LLM 위키 루트 위치와 이름을 정합니다.
  - 정확한 경로와 이름: **확인 필요**
- 프로젝트 지식을 목적에 따라 나눌 수 있도록 최소한의 하위 디렉토리 구조를 정합니다.
  - 구체적인 분류와 디렉토리 이름: **확인 필요**
- 깃이 빈 디렉토리를 추적하지 않으므로 각 디렉토리에 용도와 작성 범위만 설명하는 최소 안내 파일을 둡니다.
- 기존 `AGENTS.md`, `CLAUDE.md`, 에이전트 스킬의 역할은 유지하고 위키 구조만 추가합니다.

검토한 대안과 선택 이유

- 처음부터 위키 본문과 자동 연동까지 함께 구현하면 범위와 의사결정이 커지므로 이번 작업에서는 제외합니다.
- 특정 에이전트 전용 위치에 두면 다른 에이전트가 공통으로 사용하기 어려우므로 저장소 공용 구조를 우선합니다.
- 외부 위키를 먼저 도입하면 여러 피시에서 별도 인증과 동기화가 필요하므로, 현재 깃 작업 흐름을 활용할 수 있는 저장소 내부 구조부터 마련합니다.

---

## Tasks

- [ ] LLM 위키 루트 디렉토리의 위치와 이름 확정
- [ ] 최소 하위 디렉토리 분류와 각 역할 정의
- [ ] 위키 루트 및 하위 디렉토리 생성
- [ ] 각 디렉토리에 용도를 설명하는 최소 안내 파일 추가
- [ ] 기존 에이전트 설정 및 문서와 역할이 겹치지 않는지 확인
- [ ] 후속 문서 작성 및 에이전트 연동 범위 정리

---

## Constraints

- 이번 변경은 디렉토리 구조와 이를 유지하기 위한 최소 안내 파일로 제한합니다.
- 기존 애플리케이션 코드와 실행 동작을 변경하지 않습니다.
- 기존 `AGENTS.md`, `CLAUDE.md`, `.agents`, `.claude` 구조를 변경하지 않습니다.
- 특정 에이전트에 종속되지 않는 공용 구조여야 합니다.
- 시크릿, 환경 변수, 개인별 로컬 정보는 위키에 포함하지 않습니다.
- 추후 구조 확장이 가능하되 현재 필요가 확인되지 않은 디렉토리는 미리 만들지 않습니다.

---

## Definition of Done

- [ ] LLM 위키의 루트와 최소 하위 디렉토리 구조가 저장소에 추가됨
- [ ] 각 디렉토리의 목적과 작성 범위를 안내 파일에서 확인할 수 있음
- [ ] 새 구조가 깃에서 정상적으로 추적됨
- [ ] 기존 애플리케이션 코드와 에이전트 설정에 변경이 없음
- [ ] 후속 작업 범위가 위키 본문 작성, 에이전트 연동, 자동화로 분리되어 있음
- [ ] `npm run lint` 통과
- [ ] `npm run build` 통과
